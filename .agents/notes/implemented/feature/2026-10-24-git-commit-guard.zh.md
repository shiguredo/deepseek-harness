# Agent Note: Git commit guard as a built-in plugin

Status: implemented

[English](2026-10-24-git-commit-guard.md) | 中文

## 问题

智能体自行执行 `git commit` 会把未经用户批准的工作写入历史。工具限制、提示词指令与审批策略都没有专门针对提交：一个部署可以允许所有 shell 命令，却仍希望在历史改变前确认一次。把两个问题合并成一个开关时还会互相冲突：新会话应当做什么，以及用户改变主意后已有会话应当做什么。

同一能力最初以本地 profile bundle 实现，使用一次性令牌和全局开关。该设计在使用中逐渐暴露问题：带过期时间的令牌会允许用户在改变主意之后继续提交；全局标志无法表达某个会话单独退出；固定的"开启"默认值在无人值守运行时只能通过修改 profile 状态关闭。

## 决定

本文的决定已被取代：提交守卫不在发布内容中，[Git 推送守卫](2026-10-26-git-push-guard.zh.md)改为守卫 `git push`。下述设计与替代方案仍解释当前发布的守卫。

在 Web bundle 中发布 `@deepseek-ai/dsh-git-commit-guard`（Host）与 `@deepseek-ai/dsh-client-ui-git-commit-guard`（浏览器）。Host 插件在 `tools/pre-execute` 中检查 `bash` 与 `terminal_send` 调用里的提交类 Git 子命令。当目标会话的守卫开启时，它通过一次结构化的 `userQuestions` 提问点名确切命令；选择 `Allow` 会交给下一个监听器，其他任何结果都返回模型可见的拒绝，提问失败或调用被取消则失败关闭。不存在令牌、过期时间或预先批准状态。

两个设置被刻意分开。`stateFile` 保存 `{ default, sessions }`：`defaultEnabled` 设置此后创建的新会话的默认值，输入框芯片修改单个会话。没有存储选择的会话在首次使用时捕获当前默认值，因此修改默认值不会覆盖已有会话。已发布的浏览器界面是输入框芯片与插件页面中“时雨堂内置插件设置”分组的卡片。该包不添加侧边栏条目；卡片写入同一状态路由，`defaultEnabled` 在任何浏览器写入之前提供初始值。两个层级都由同一个同源 `GET|POST /commit-guard/state` 路由提供；路由在回答前调用 `connection` 服务的 `requestRejection` 检查，由 Connection 的 Host/Origin 与身份验证检查保护控制面。

该插件不添加 Git 钩子，也不在仓库中安装任何内容。shell 识别明确只是便利，不是沙箱：智能体写进脚本中的提交不会被检测，README 说明了这一限制。

## 考虑过的替代方案

- **审批接缝的 `ask` 决定加过期令牌。** 最初的 profile 本地版本使用十分钟过期的一次性令牌。令牌会悄悄放行之后的提交，而在 `never` 审批策略下，管线的 `ask` 根本无法触达用户。每次尝试都提问且不存储批准，取代了两者，并让每次决定作为工具结果在会话记录中可审计。
- **以 Git 钩子（prek、lefthook 或普通 pre-commit 钩子）作为执行点。** 钩子能拦截脚本中的提交，但需要仓库本地配置，会与仓库自身的钩子管理器冲突，也无法向用户显示确切待执行的命令。它被实现、验证，随后从发布功能中移除；工具层守卫仍是受支持的界面。
- **仅使用一个 profile 级开关。** 最简单，但无法表达"仅此会话"，一处修改会静默改写所有会话的态势。默认值与每会话的拆分保留了全局答案，同时允许单个会话退出而无需批量应用。
- **专用斜杠命令用于切换。** Host 设计最初包含 `/commit-guard on|off`。每个命令都会向会话记录写入 `command/run` 与 `command/done`，把偏好修改变成对话内容；Web 路由让控制不进入会话记录。
- **用于默认值设置的侧边栏页面。** profile 本地版本带有左窗格页面和键控主面板。内置插件不应给每个 profile 增加导航负担，因此发布包把默认值放进插件页面中自己独立的“时雨堂内置插件设置”分组，并保留用于单个会话的输入框芯片。
- **从会话事件或投影推导设置。** 切换不是用户消息，插件也无法追加新的事件类型；投影将需要合成事件。由插件拥有的小状态文件让选择持久化，而无需扩大会话格式。

## 影响

- 确认需要已连接的 Web 回答方。无头组合、已关闭的页面与子智能体无法回答，因此那里的受守卫提交会一直阻断；README 告知无人值守部署保持守卫关闭。
- Web bundle 现在默认运行该守卫，因此新 profile 在第一次智能体提交前会询问。不需要它的部署可以移除该行或把 `defaultEnabled` 设为 false；守卫仍需要 `webServer` 与 `connection` 服务，缺少时不会激活。
- 内置插件设置卡片就是默认值设置界面；运维人员仍可通过 `defaultEnabled` 配置提供或覆盖它，用户也可从输入框芯片让单个会话退出。
- shell 识别覆盖两个已发布的 shell 工具与常见包装形式；未来能创建提交的工具必须显式加入，并记入包 README 的限制。
- 设置变更本身不记录在会话记录中。之后的读者无法重建是谁修改了守卫；拒绝结果与问题回答仍是可审计的产物。
- 包测试覆盖路由、监听器、状态捕获与客户端组件。真实组合的 Loader 测试与浏览器界面录制的会话快照仍未完成；它们是在该功能被视为可发布之前的下一个验证步骤。

## 测试

`packages/guard/git-push-guard/tests` 覆盖提交守卫所设计的 pre-execute 决策路径（允许、拒绝、无法触达回答方、子智能体、无智能体、取消）、状态文件（首次使用时捕获、畸形输入）与提示词段落。`packages/client/ui-git-push-guard/tests` 用打桩的路由覆盖插件注册与输入框芯片。提交守卫自身的包从未发布，因此没有测试目录以它命名。变更中运行了仓库门禁：类型检查、lint、包 README 门禁、翻译配对、配置目录与依赖策略。
